1. Зачем Angular: чем он отличается от Vue и Nuxt #

Vue — библиотека, к которой вы сами подбираете роутер, стор, HTTP-клиент и библиотеку форм. Nuxt добавляет к Vue соглашения и сервер. Angular — платформа: всё перечисленное входит в коробку, написано одной командой, выходит одной версией и спроектировано вместе.

Цена — больше понятий на входе: компоненты-классы, декораторы, DI, провайдеры. Выигрыш — предсказуемость. В большом проекте на Angular с десятью командами код выглядит одинаково, потому что фреймворк решил за вас, где лежит состояние, как ходить в сеть и как защищать маршруты. Поэтому Angular так распространён в корпоративных системах (банки, CRM, внутренние порталы) — ровно в той нише, к которой относится RoomBook.

ГЛАВНАЯ МЫСЛЬ ЛАБЫ Современный Angular — это сигналы + DI. Сигнал отвечает на вопрос «что изменилось и кого перерисовать», DI — «откуда компонент берёт то, что ему нужно». С Angular 21 нет zone.js, с Angular 22 компоненты по умолчанию OnPush: фреймворк больше не проверяет всё дерево «на всякий случай», а обновляет только то, что читает изменившийся сигнал. Почти все баги лабы — это код, который меняет данные в обход сигналов, или сервис, созданный не на том уровне DI.

2. Азбука Angular — каждое понятие на примере RoomBook #

Четырнадцать понятий, без которых не прочитать ни одного Angular-проекта. В сессиях 1–2 вы напишете их руками.

2.1 Компонент

Класс с декоратором @Component: селектор (имя тега), шаблон, стили и список того, что шаблон использует. С Angular 19 все компоненты standalone по умолчанию: NgModule больше не нужен.

import { Component, input, output } from '@angular/core';
import type { Room } from '../models';

@Component({
  selector: 'app-room-card',            // <app-room-card> в шаблонах
  template: `
    <h3>{{ room().name }}</h3>
    <p>до {{ room().capacity }} человек</p>
    <button (click)="book.emit(room().id)">Забронировать</button>
  `,
})
export class RoomCard {
  readonly room = input.required<Room>();     // входной параметр — сигнал
  readonly book = output<number>();            // событие наружу
}

С Angular 20 CLI генерирует имена без суффикса: RoomCard в файле room-card.ts, а не RoomCardComponent в room-card.component.ts. В старых проектах вы увидите старую схему — это одно и то же.

2.3 Сигналы

Сигнал — значение, которое знает, кто его читает.

const date = signal('2026-09-28');                 // записываемый
const isToday = computed(() => date() === today()); // вычисляемый, кешируется
date.set('2026-09-29');                             // запись
date.update(d => nextDay(d));                       // запись через функцию
effect(() => console.log('дата', date()));          // побочный эффект при изменении

Чтение — вызов функции: date(). Шаблон, который прочитал date(), перерисуется при set. Подробно — в разделе 3.

2.4 input(), output(), model()

Функции вместо старых декораторов @Input/@Output. input() возвращает сигнал только для чтения, model() — записываемый сигнал с двусторонней привязкой: родитель пишет [(date)]="selectedDate", ребёнок — this.date.set(...).

2.5 Сервис и inject()

Класс с логикой, которую не должен знать компонент: запросы к API, состояние, правила. Компонент получает его через DI.

@Injectable({ providedIn: 'root' })        // один экземпляр на всё приложение
export class RoomsApi {
  private readonly http = inject(HttpClient);
  list(params: RoomFilter) { return this.http.get<Room[]>('/api/rooms', { params: { ...params } }); }
}

export class RoomList {
  private readonly api = inject(RoomsApi);  // DI: Angular сам найдёт или создаст экземпляр
}

2.6 Провайдеры

Провайдер — инструкция «как получить зависимость»: класс, готовое значение, фабрика. Где провайдер объявлен, там и живёт экземпляр: в providedIn: 'root' — один на приложение, в providers: [] компонента — свой у каждого экземпляра компонента. Раздел 4.

2.7 InjectionToken

Ключ DI для того, что не является классом: конфигурация, строка, функция. const API_DELAY = new InjectionToken<number>('API_DELAY').

2.8 Директивы и pipes

Директива — поведение без собственного шаблона, навешенное на элемент ([appAutofocus]). Pipe — чистая функция для шаблона: встроенные date, currency, async, свои — @Pipe({ name: 'duration' }).

2.9 Роутер

Маршруты — массив объектов в app.routes.ts. Место для страницы — <router-outlet />, ссылка — <a routerLink="/rooms">. Параметры маршрута можно получать прямо как input() компонента (withComponentInputBinding). Раздел 6.

2.10 HttpClient и интерцепторы

HTTP-клиент возвращает Observable. Интерцептор — функция, через которую проходит каждый запрос и ответ: подставить токен, залогировать, обработать 401. С Angular 22 под капотом по умолчанию fetch. Раздел 8.

2.11 resource и httpResource

Асинхронные данные как сигнал. Параметры — сигналы; изменились — запрос перезапустился, а предыдущий отменён. Стабильны с v22.

readonly rooms = httpResource<Room[]>(() => ({ url: '/api/rooms', params: { minCapacity: this.minCapacity() } }));
// rooms.value(), rooms.isLoading(), rooms.error(), rooms.reload()

2.12 Signal Forms

Формы, в которых источник правды — сигнал с моделью, а валидация описана схемой. Стабильны с v22.

readonly model = signal({ title: '', start: '10:00', end: '11:00' });
readonly bookingForm = form(this.model, (p) => {
  required(p.title, { message: 'Укажите тему встречи' });
});
// в шаблоне: <input [formField]="bookingForm.title">

2.13 RxJS

Библиотека потоков событий: Observable, операторы (debounceTime, switchMap, retry). После появления сигналов нужна реже, но остаётся для событий во времени: поиск с отменой, WebSocket и SSE, повтор запросов. Мост — toSignal() и toObservable(). Раздел 5.

3. Реактивность: сигналы, OnPush и почему в Angular 22 нет zone.js #

Раньше Angular узнавал об изменениях через zone.js: библиотека подменяла setTimeout, addEventListener, fetch и после каждого такого события запускала проверку всего дерева компонентов. Работало «само», но дорого и непрозрачно. С Angular 21 новые проекты создаются без zone.js (zoneless), а с Angular 22 компоненты по умолчанию используют стратегию OnPush.

Что запускает перерисовку компонента (zoneless + OnPush)Пример
изменился сигнал, прочитанный в шаблонеthis.date.set(...)
изменился input() (новая ссылка)родитель передал новый массив
событие шаблона этого компонента(click)
новое значение async pipe{{ obs$ | async }}
НЕ запускаетмутация обычного поля или массива: this.rooms.push(x), setTimeout(() => this.count++)

Отсюда главное правило: состояние, которое видит шаблон, хранится в сигналах и меняется заменой, а не мутацией.

readonly rooms = signal<Room[]>([]);
this.rooms.update(list => [...list, newRoom]);        // ✅ новая ссылка — сигнал уведомит читателей
this.rooms().push(newRoom);                             // ❌ тот же массив — сигнал не узнает

EFFECT — ПОСЛЕДНЕЕ СРЕДСТВО Если хочется в effect записать в другой сигнал — почти всегда нужен computed или linkedSignal. Эффект, который синхронизирует сигналы между собой, создаёт лишние циклы перерисовки и трудноуловимые баги порядка.
🔬 Под капотом: как сигнал «знает», кто его читает

При выполнении computed, effect или шаблона Angular выставляет «текущего потребителя». Каждый вызов sig() регистрирует сигнал как зависимость этого потребителя. При set сигнал помечает зависимых потребителей «грязными» (push), а пересчёт происходит лениво, когда значение снова нужно (pull). Шаблон компонента — тоже потребитель. Поэтому zoneless-Angular знает, какие компоненты перерисовать, и не проверяет остальные. Та же идея, что у reactive/effect во Vue и в Proxy-сторе JS-лабы, только без Proxy: зависимость регистрирует явный вызов функции.

4. Dependency Injection под капотом #

DI — ответ на вопрос «откуда компонент берёт сервис». Компонент не создаёт зависимости (new RoomsApi()), а просит их у инжектора. Инжекторы образуют дерево:

EnvironmentInjector (root)        ← providedIn: 'root', providers в app.config.ts
 └─ инжекторы lazy-маршрутов       ← providers: [] в конфигурации маршрута
     └─ ElementInjector AppShell    ← providers: [] в @Component
         └─ ElementInjector BookingPage
             └─ ElementInjector BookingForm  ← inject(X): ищет вверх до первого провайдера X

inject(X) идёт от текущего компонента вверх по дереву и берёт экземпляр у первого инжектора, где X предоставлен. Не нашёл — ошибка NullInjectorError.

Где объявлен провайдерСколько экземпляровКогда в RoomBook
@Injectable({ providedIn: 'root' })один на приложение, создаётся при первом inject; tree-shakableRoomsApi, AuthStore, BookingsStore
providers в app.config.tsодин на приложениеprovideRouter, provideHttpClient, токены конфигурации
providers маршрутаодин на этот раздел, пока он загруженсервисы админки
providers компонентасвой у каждого экземпляра компонента и его детейсостояние одной формы брони (шаг 2.1)

Виды провайдеров: { provide: X, useClass: Y } — подменить реализацию (в тестах — фейк), useValue — готовое значение, useFactory — вычислить при создании, useExisting — алиас.

ГДЕ МОЖНО ВЫЗЫВАТЬ inject() Только в контексте инъекции: в инициализаторах полей класса, в конструкторе, в фабриках провайдеров и в функциональных guards/interceptors/resolvers. В методе, вызванном по клику, или в setTimeout — ошибка NG0203. Зависимости берутся полями класса, а не внутри методов.

5. RxJS в 2026 году: где он всё ещё нужен #

До сигналов RxJS был везде: состояние в BehaviorSubject, шаблоны через | async. Теперь состояние — это сигналы, а RxJS остаётся для того, в чём он сильнее: событий во времени.

HTTP-клиент и интерцепторыObservableAPI HttpClient построен на нём

const query = signal('');

  { initialValue: [] },

Интерцептор — функция (req, next) => Observable. Запрос неизменяем: чтобы добавить заголовок, его клонируют.

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthStore).token();
  return next(token ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }) : req);
};

Порядок в массиве важен: запрос проходит интерцепторы слева направо, ответ — справа налево. Логгер первым видит и исходный запрос, и итоговый ответ.

@Component({
  selector: 'app-rooms-page',
  imports: [RoomGrid, RoomFilters],
  template: `
    <main>
      <h1>Переговорные</h1>
      <app-room-filters [(minCapacity)]="minCapacity" [(equipment)]="equipment" />

  protected readonly rooms = signal(MOCK_ROOMS);
  protected readonly minCapacity = signal(Number(localStorage.getItem(STORAGE_KEY) ?? 1));
  protected readonly equipment = signal<Equipment | ''>('');

  protected readonly filtered = computed(() =>
    this.rooms().filter(r =>
      r.capacity >= this.minCapacity() && (!this.equipment() || r.equipment.includes(this.equipment() as Equipment))));

  // выбор сохраняется, пока комната в списке; иначе — первая подходящая
  protected readonly selectedId = linkedSignal<Room[], number | null>({
    source: this.filtered,
    computation: (list, previous) =>
      previous && list.some(r => r.id === previous.value) ? previous.value : (list[0]?.id ?? null),
  });

  protected readonly selectedName = computed(() =>
    this.rooms().find(r => r.id === this.selectedId())?.name ?? '—');

  constructor() {
    effect(() => localStorage.setItem(STORAGE_KEY, String(this.minCapacity())));
  }

  protected onBook(id: number) { console.log('бронировать комнату', id); }
}

🔬 Под капотом: как было с zone.js и почему от него отказались

zone.js патчил все асинхронные API браузера. После любого setInterval, промиса или события Angular запускал проверку дерева компонентов сверху вниз, и сломанная версия выше работала бы: часы шли бы, потому что каждую секунду проверялось всё. Сигналы дают Angular точное знание, что изменилось, и обходить дерево «на всякий случай» больше не нужно. Старое поведение компонента можно включить явно — changeDetection: ChangeDetectionStrategy.Eager (так в v22 называется бывший Default), но в новом коде это не нужно.

      } @else {

  private readonly base = inject(API_BASE_URL);

  protected readonly minCapacity = signal(Number(localStorage.getItem(STORAGE_KEY) ?? 1));
  protected readonly equipment = signal<Equipment | ''>('');

  // функция читает сигналы → при их изменении запрос перезапускается, предыдущий отменяется
  protected readonly rooms = httpResource<Room[]>(() => ({
    url: `${this.base}/rooms`,
    params: { minCapacity: this.minCapacity(), ...(this.equipment() ? { equipment: this.equipment() } : {}) },
  }));

  // value() у ресурса в состоянии ошибки бросает исключение — читаем через hasValue()
  protected readonly list = computed(() => (this.rooms.hasValue() ? this.rooms.value() : []));

  protected readonly selectedId = linkedSignal<Room[], number | null>({
    source: this.list,
    computation: (list, prev) => (prev && list.some(r => r.id === prev.value) ? prev.value : (list[0]?.id ?? null)),
  });
  protected readonly selectedName = computed(() => this.list().find(r => r.id === this.selectedId())?.name ?? '—');

    effect(() => localStorage.setItem(STORAGE_KEY, String(this.minCapacity())));
  }

  protected onBook(id: number) { console.log('бронировать комнату', id); }
}

Ответы приходят в случайном порядке, и победителем становится последний пришедший, а не последний отправленный: введено «эль», а показан результат для «ла». // web/src/app/core/interceptors.ts
import { HttpErrorResponse, type HttpInterceptorFn } from '@angular/common/http';
import { inject } from '@angular/core';
import { catchError, finalize, throwError } from 'rxjs';
import { ToastService } from '../shared/toast';

// 1. Лог: метод, адрес, статус, время
export const apiLogInterceptor: HttpInterceptorFn = (req, next) => {
  const started = performance.now();
  let status: number | string = '…';
  return next(req).pipe(
    catchError((err: unknown) => {
      status = err instanceof HttpErrorResponse ? err.status : 'error';
      return throwError(() => err);
    }),
    finalize(() => {
      if (status === '…') status = 'ok';
      console.log(`[api] ${req.method} ${req.urlWithParams} → ${status} (${Math.round(performance.now() - started)} мс)`);
    }),
  );
};

// 2. Ошибки, которые пользователь не может исправить сам: сеть и 5xx
export const errorInterceptor: HttpInterceptorFn = (req, next) => {
  const toast = inject(ToastService);                 // функциональный интерцептор — контекст инъекции
  return next(req).pipe(
    catchError((err: unknown) => {
      if (err instanceof HttpErrorResponse && (err.status === 0 || err.status >= 500)) {
        toast.show(err.status === 0 ? 'Нет связи с сервером' : `Ошибка сервера (${err.status})`, 'error');
      }
      return throwError(() => err);                   // 4xx пробрасываем: их разбирает вызывающий код
    }),
  );
};

Зачем: свободен ли слот, знает только сервер — это асинхронное правило. validateHttp строит запрос из значений полей (request возвращает то же, что принимает httpResource: строку или объект с params), а при изменении любого прочитанного поля отменяет старый запрос и отправляет новый. Асинхронная проверка запускается только после успешных синхронных: при «конец раньше начала» бесполезного запроса не будет. onSuccess означает «проверка выполнилась», а не «всё хорошо»: занятость — это тоже успешный ответ, и из него строится ошибка. onError — сбой самой проверки (сеть, 5xx). Запрос идёт через HttpClient, поэтому к нему применяются интерцепторы: токен, лог и тост при 5xx.

// web/src/app/core/bookings-store.ts — ❌ сначала СЛОМАННАЯ ВЕРСИЯ (без сброса при смене пользователя)
import { Injectable, computed, inject, signal } from '@angular/core';
import { HttpErrorResponse } from '@angular/common/http';
import { firstValueFrom } from 'rxjs';
import { BookingsApi, type BookingDraft } from './bookings-api';
import { ToastService } from '../shared/toast';
import { todayIso } from './time';
import type { Booking } from './models';

@Injectable({ providedIn: 'root' })
export class BookingsStore {
  private readonly api = inject(BookingsApi);
  private readonly toast = inject(ToastService);

  readonly my = signal<Booking[]>([]);
  readonly loaded = signal(false);
  readonly upcoming = computed(() => this.my().filter(b => b.date >= todayIso()));

  async load(force = false) {
    if (this.loaded() && !force) return;               // кеш: второй заход на страницу без запроса
    this.my.set(await firstValueFrom(this.api.my()));
    this.loaded.set(true);
  }

  async create(roomId: number, draft: BookingDraft) {
    const created = await firstValueFrom(this.api.create(roomId, draft));
    this.my.update(list => [...list, created].sort((a, b) => (a.date + a.start).localeCompare(b.date + b.start)));
    return created;
  }

  async cancel(id: number) {
    const before = this.my();
    this.my.update(list => list.filter(b => b.id !== id));        // оптимистично: убрали сразу
    try {
      await firstValueFrom(this.api.cancel(id));
      this.toast.show('Бронь отменена');
    } catch (e) {
      if (e instanceof HttpErrorResponse && e.status === 404) return;   // уже отменена где-то ещё — это успех
      this.my.set(before);                                          // откат
      this.toast.show('Не удалось отменить бронь', 'error');
    }
  }
}

Зачем: SSE — поток событий во времени, и Observable описывает его естественно: new Observable(subscriber => …) открывает соединение при подписке и возвращает функцию очистки, которая закроет его при отписке. Без share() каждый подписчик открывает своё соединение. Без takeUntilDestroyed() подписка переживает компонент: уничтоженные расписания продолжают слушать события и дёргать reload(), а соединения копятся. Браузер держит не больше шести соединений к одному хосту по HTTP/1.1, и седьмое открытое расписание перестанет загружаться вообще. share() держит одно соединение, пока есть хотя бы один подписчик, и закрывает его, когда подписчиков не осталось. takeUntilDestroyed() без аргумента работает в контексте инъекции (конструктор, поле) и сам берёт DestroyRef компонента или сервиса. Токен в query — вынужденная мера EventSource: такой адрес попадает в логи прокси, в реальных системах используют короткоживущий одноразовый токен для SSE.

// web/src/app/shared/duration-pipe.ts
import { Pipe, type PipeTransform } from '@angular/core';

@Pipe({ name: 'duration' })                   // pure по умолчанию: пересчёт только при смене аргументов
export class DurationPipe implements PipeTransform {
  transform(start: string, end: string): string {
    const toMin = (t: string) => Number(t.slice(0, 2)) * 60 + Number(t.slice(3, 5));
    const m = toMin(end) - toMin(start);
    const h = Math.floor(m / 60);
    return [h ? `${h} ч` : '', m % 60 ? `${m % 60} мин` : ''].filter(Boolean).join(' ') || '0 мин';
  }
}

import { Component, computed, inject, input } from '@angular/core';
import { httpResource } from '@angular/common/http';
import { API_BASE_URL } from '../core/tokens';
import { addDays, todayIso } from '../core/time';
import type { Booking } from '../core/models';

@Component({
  selector: 'app-week-overview',
  template: `
    <h3>Загрузка на неделю</h3>
    @for (d of days(); track d.date) {
      <div class="day"><span>{{ d.date }}</span>
        <div class="bar"><div class="fill" [style.width.%]="d.percent"></div></div>
        <span class="muted">{{ d.hours }} ч</span></div>
    }
  `,
  styles: `
    .day { display: grid; grid-template-columns: 110px 1fr 50px; gap: 8px; align-items: center; margin: 4px 0; }
    .bar { background: #eee; height: 10px; border-radius: 5px; } .fill { background: #c3002f; height: 100%; border-radius: 5px; }
  `,
})
export class WeekOverview {
  readonly roomId = input.required<string>();
  private readonly base = inject(API_BASE_URL);
  private readonly all = httpResource<Booking[]>(() => ({ url: `${this.base}/bookings`, params: { roomId: this.roomId() } }));

  protected readonly days = computed(() => {
    const list = this.all.hasValue() ? this.all.value() : [];
    return Array.from({ length: 7 }, (_, i) => {
      const date = addDays(todayIso(), i);
      const minutes = list.filter(b => b.date === date).reduce((sum, b) =>
        sum + (Number(b.end.slice(0, 2)) * 60 + Number(b.end.slice(3))) - (Number(b.start.slice(0, 2)) * 60 + Number(b.start.slice(3))), 0);
      return { date, hours: +(minutes / 60).toFixed(1), percent: Math.min(100, (minutes / (12 * 60)) * 100) };
    });
  });
}

Зачем: pipe — чистое преобразование для шаблона: pure pipe пересчитывается только при смене аргументов и переиспользуется в любом компоненте. @defer — ленивая загрузка на уровне части шаблона, а не маршрута. Всё, что используется только внутри блока (здесь WeekOverview), компилятор выносит в отдельный чанк, и он скачивается по триггеру: on viewport, on interaction, on idle, when условие. @placeholder показывается до триггера, @loading — пока грузится чанк; minimum 300ms убирает мелькание. Данные тоже запрашиваются только после появления блока: пока компонента нет, нет и его httpResource.

import { Injectable, signal } from '@angular/core';

export interface RuntimeConfigData { apiBase: string; supportEmail: string }

@Injectable({ providedIn: 'root' })
export class RuntimeConfig {
  private readonly data = signal<RuntimeConfigData>({ apiBase: '/api', supportEmail: '' });
  readonly apiBase = () => this.data().apiBase;
  readonly supportEmail = () => this.data().supportEmail;

  async load() {
    const res = await fetch('/config.json', { cache: 'no-store' });   // fetch, а не HttpClient: интерцепторам тут не место
    if (res.ok) this.data.set(await res.json());
  }
}

Зачем: ng build кладёт в dist/web/browser статику с хешами в именах файлов. Хешированные файлы кешируются навсегда (immutable), а index.html — никогда, иначе после деплоя пользователи получат старый HTML со ссылками на удалённые чанки. try_files … /index.html — SPA-fallback: /rooms/3/schedule — не файл на диске, nginx должен отдать приложение, а маршрут разберёт Angular. Без этого F5 на любой странице, кроме главной, даёт 404. Прокси /api в nginx повторяет proxy.conf.json из dev; для SSE отключена буферизация, иначе события копились бы в nginx. Runtime-конфиг решает ту же задачу, что runtimeConfig в Nuxt-лабе: один образ для всех окружений, а адреса и контакты подкладываются файлом при запуске. provideAppInitializer задерживает старт приложения, пока конфиг не загружен. Бюджеты в angular.json (budgets) роняют сборку, если начальный бандл вырос сверх лимита, — простая защита от случайного импорта тяжёлой библиотеки.

12. Глоссарий #

Standalone-компонент — компонент без NgModule; зависимости шаблона перечислены в imports. По умолчанию с v19.
Сигнал (signal) — реактивное значение; чтение sig() регистрирует зависимость, запись уведомляет читателей.
computed — вычисляемый сигнал с кешем; пересчитывается лениво при изменении зависимостей.
effect — функция, перезапускаемая при изменении прочитанных сигналов; для побочных эффектов во внешний мир.
linkedSignal — записываемый сигнал, который пересчитывается при изменении источника.
resource / httpResource — асинхронное значение как сигнал с состояниями loading/error и отменой.
OnPush — стратегия, при которой компонент перерисовывается только по сигналам, новым input и своим событиям. По умолчанию с v22.
Zoneless — работа без zone.js: Angular узнаёт об изменениях из сигналов, а не из перехвата асинхронных API. По умолчанию с v21.
ChangeDetectionStrategy.Eager — прежняя стратегия Default под новым именем в v22: проверка при каждом цикле.
Инжектор — контейнер DI; инжекторы образуют дерево, inject() ищет провайдер вверх по нему.
Провайдер — инструкция, как получить зависимость: useClass, useValue, useFactory, useExisting.
Контекст инъекции — место, где работает inject(): инициализаторы полей, конструктор, фабрики, функциональные guards/interceptors/resolvers.
InjectionToken — ключ DI для значений, которые не являются классами.
Интерцептор — функция (req, next), через которую проходит каждый HTTP-запрос и ответ.
Холодный Observable — поток, который начинает работу при подписке и заново для каждого подписчика (как HttpClient.get).
switchMap — оператор, отменяющий предыдущий внутренний поток при новом значении.
share() — делает поток общим для подписчиков; закрывает источник, когда их не осталось.
toSignal / toObservable — мост между RxJS и сигналами.
takeUntilDestroyed — завершает подписку при уничтожении компонента или сервиса.
Guard — функция, разрешающая навигацию: canActivate, canMatch, canDeactivate, canActivateChild.
Resolver — функция, загружающая данные до входа на маршрут.
UrlTree / RedirectCommand — редирект, возвращаемый из guard или resolver.
Layout-маршрут — маршрут без пути с компонентом-оболочкой и дочерними маршрутами.
Signal Forms — формы с моделью в сигнале и схемой правил; [formField], validate, validateHttp, submit. Стабильны с v22.
Field tree — дерево полей формы: f.title — поле, f.title() — его состояние.
FormValueControl — интерфейс своего контрола для Signal Forms: value = model().
Reactive Forms — формы на FormGroup/FormControl с валидаторами-функциями и valueChanges.
ControlValueAccessor — интерфейс своего контрола для Reactive/Template-driven форм (4 метода).
Pipe — преобразование значения в шаблоне; pure пересчитывается только при смене аргументов.
@defer — ленивая загрузка части шаблона по триггеру, с @placeholder и @loading.
TestBed — тестовое окружение Angular с настраиваемыми провайдерами.
SPA-fallback — отдача index.html на любой неизвестный путь, чтобы маршрут разобрал клиентский роутер.
